How this was built

This site makes a narrow promise: every number on it can be traced to the code that computed it, and every claim was tested by someone trying to break it. This page explains how that works, who did what, and what happens when a check fails.

Every number is a claim in a ledger

The analysis code does not print numbers for a person to copy. Each number is registered as a claim with an id, a plain-language definition, the number of records behind it and the time it was computed, and written to a JSON ledger. There are claims in 9 ledger files. The pages are generated from the ledger by scripts/build_site.py; only the prose is written by hand.

Click any underlined number on the site to see its definition and n. The Data and methods page has the whole ledger, searchable, and every ledger file is downloadable.

A test checks every number on every page

tests/test_site_claims.py reads every generated page, finds every number that links to a claim, and checks that the claim exists and that the number matches it at the precision it is written with. If the analysis is re-run and the site is not rebuilt, or if anyone edits a page by hand, the test fails. The test suite runs on every change to the repository.

Claims were reviewed by reviewers trying to refute them

Before this version was written, the project's earlier README was put through an adversarial review from five angles: machine-learning method, fire science, reproducibility, responsible AI, and conservation. Each reviewer re-ran its own code on the data and was asked to argue against the project as hard as the evidence allowed. Of its sentences, were supported, weakened, refuted and unverifiable. The fire-duration model and the "control efficiency score" did not survive and were retired; the large-fire ranking model on the Prediction page replaced them. Report: docs/review/PANEL_REPORT.md.

The first public site was audited the same way: each analysis rebuilt from the original sources, its numbers replicated, then tested more strictly. See the audit.

When a check fails, the correction stays visible

Claims that were wrong are not quietly removed. The errata list each one: what was claimed, what the check found, and the evidence. When an input dataset is missing or a number cannot be computed, the page says so instead of estimating it.

Who did what

Robyn Collie chose the questions, directed the work, and decided what was published and how it is worded. Most of the code, the analysis runs and the adversarial reviews were done by Claude Code, an AI coding agent from Anthropic, working in sessions Robyn directed; the repository's commit history records which commits it wrote. The safeguards above are there partly for that reason: a number is trusted because it is in the ledger and passes the tests, not because a person or an agent typed it.
